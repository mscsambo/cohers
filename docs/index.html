COHERS · Community Reporting, Verification & Early Warning

COHERS Case Flow

How a report moves from a villager's Telegram message to a closed case, who acts at each step, and which Telegram notifications each role receives. Written from the running pilot configuration.

Who takes part

Telegram bot

Community reporter

Registers in the bot (Khmer or English), submits reports with location, description and photos, answers officer questions, follows progress with the reference code.

Telegram bot

Focal point · VHSG / CAO

Receives assigned cases with action buttons. VHSG handles human health; CAO handles animal health and environment. Acknowledges, verifies in the field, asks questions, escalates, submits findings.

Dashboard + Telegram alerts

District officer

Sees only their own districts. Does manual triage, reassigns, reviews and resolves escalations, links duplicate reports, and approves closure or reopens.

Dashboard + optional alerts

System administrator

Manages accounts, geography, the Focal Point Router, AI and Telegram configuration. Monitors every district and may correct an assignment, but cannot close cases or resolve escalations.

From report to closure

  1. Reporter · Telegram

    Submit the report

    • 📝 Submit Report → district → commune → village → what happened → how many affected → when → up to 3 photos and an optional location pin → review → Submit.
    • The bot answers at once with a reference code like COH-2026-000151. Pressing Submit twice never creates two reports.
  2. COHERS · automatic, seconds

    Intake and triage

    • Saves the original text unchanged, downloads photos to private storage, and flags a possible duplicate (same commune, similar text, last 3 days). Nothing is deleted or rejected automatically.
    • AI (Gemini, or the offline keyword classifier) suggests a category and priority. This is advisory only. Safety rules (for example "person died", "chemical", "many dead") can raise the priority.
    • Uncertain, failed or unknown classification → status Triage Review for a person to classify.
    • CRITICAL priority opens a district escalation at the same time as routing continues.
  3. COHERS · Focal Point Router

    Route to a field officer

    • Looks for the primary officer of the right type at village → commune → district, then the backup.
    • Found → status Assigned, with an acknowledgement deadline set by priority.
    • Nobody found → status Triage Review and a No officer escalation to the district.
  4. VHSG / CAO · Telegram

    Field response

    • Acknowledge → Acknowledged (accepted, not yet verified). Start verification → Verifying.
    • Request info → the reporter gets the question with a Reply button; status Needs Info until they answer.
    • Escalate with a reason → district escalation; the officer keeps the case.
    • Submit findings with notes → Verified, Rejected or Duplicate (linked under one incident). "Follow-up needed" also opens an escalation.
  5. District officer · dashboard

    District review

    • Classifies Triage Review cases (manual triage), which routes them to an officer.
    • Reviews escalations: Start review, then record a decision (follow-up directed, reassigned, more evidence, referred onward, no further action).
    • Reassigns to another eligible VHSG/CAO, and links reports describing the same event.
  6. District officer · dashboard

    Close, or reopen

    • Closure needs an officer outcome (Verified, Rejected or Duplicate) and no open escalation.
    • The district writes an internal outcome (never sent to the reporter) and an optional message to the reporter.
    • Reopen with a reason returns the case to the outcome it had. Every step is in the audit log.

Escalations run alongside the status

Tracked separately, so a Verified case can still have an open escalation. A case cannot be closed while any escalation is open.

Notifications on a typical case

Every message goes through the queue worker to the person's linked Telegram chat. Staff connect theirs in the dashboard under My Telegram; field officers use an activation link from the administrator.

The person who reassigns a case is not alerted about their own action, and the assigned officer gets the case alert rather than the staff notice. Officer notes and internal outcomes are never sent to reporters. Staff choose their alerts in My Telegram → What I receive; delivery problems appear under Admin → Alerts & Jobs.

When nobody acknowledges in time

PriorityAcknowledge withinWhen missed (checked every minute)
LOW24 hoursReminder to the officer, repeated each period; case stays in the Overdue list.
MEDIUM4 hoursReminder first; if still not acknowledged a period later, the backup officer takes over.
HIGH30 minutesBackup officer takes over and the district is alerted (Overdue escalation).
CRITICAL15 minutesDistrict is alerted at once, then again every 15 minutes, with a reminder to the officer, until someone acknowledges.

If no backup exists, a No officer escalation goes to the district. Targets are pilot values and can be changed in Admin → Language & Settings.
